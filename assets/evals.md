# evals · 端到端验收样例

> 用法：校准新 agent/新模型跑本 skill 时的最低合格线。prompt 按真实用户口吻给，expected_output 是**验收证据清单**——不足其中任何一项即不合格（expected 写必须跑过的检查与必须留存的证据，不写形容词）。

## eval 1 · 标准单支片（90s 两段）

**prompt**：帮我把「锚定效应」做成一支无口播知识情绪片。90 秒左右，横版，中文主字幕带英文小字。我只有一个要求：结尾要有一句献给×××的话。

**expected_output（全部满足才算合格）**：
- 一次问清 ≤5 问（含表现强度档位一问），或用户说「你定」后默认值在分镜表注明
- 五问门通过证据：献给句写出来了（写不出=必须停下来说明，不许硬做）
- **锚点测试通过证据**：找到「外行一眼认得」的具象锚点（锚定效应的候选：贴在价格旁边的数字标签/被 anchoring 拉走的秤），写进分镜表头并挂在主题事件或反转帧；找不到=回选题层换形象的记录，而不是硬写抽象场域
- 分镜与文案.md 为九列逐镜表；`check-storyboard.py` FAIL 0 的输出贴出
- 三候选结构发散记录 + 选中理由
- BGM 用 `gen-audio.py` 生成，impact 秒与分镜表转折秒一致；30s 小样试听确认记录（或用户免确认的台账注记）
- 风格帧拼图 + **能力展示镜样片**（3-8s 无声）发给用户确认的记录（档位对应的能力展示镜数量达标）
- 段 1 先行产出契约基准截图；seg2 工单含「先 Read 基准截图」
- 每段两轮自查记录（与对标帧并排），fail 项修复后才汇报
- 总装前 `check-build.py` FAIL 0 输出贴出（字幕逐字↔分镜表、DUR↔总时长、白闪↔白名单窗）
- 关键事件窗（白闪±2 帧、金词染色全程）全帧采样抽帧目检记录
- 技术检查 ffprobe 全 PASS 无 NOT CHECKED；审片十项观察写入 qa/review-vN.md；最后请用户亲验成片

## eval 2 · 用户只丢一个词

**prompt**：做一支关于「幸存者偏差」的片子。

**expected_output**：
- 不直接开工：先过五问门并给三候选结构，把「凌晨一点谁在搜这个」「献给句」拿给用户确认后才写九列表
- 若用户回复「你看着办」：全程走默认值，但在台账逐项注明默认选择与理由
- 其余证据同 eval 1（check-storyboard/check-build FAIL 0、样片确认、亲验请求）

## eval 3 · 中途改稿（修订成本路由）

**prompt**：（在 eval 1 进行到 seg2 渲染中时）等一下，那句金句我想改成「我们不是看见现实，是看见平均值。」另外结尾的献给句改成献给每一个被平均的人。

**expected_output**：
- 定位到修订成本路由表：字幕文案错→最早返工阶段是 Step 2 分镜表
- 改表 → 改各段 timeline.js COPY → 只重渲受影响镜所在段（不重渲未涉及段，并说明为什么）
- 改动后重跑 check-storyboard + check-build，FAIL 0 证据贴出
- 金句改动波及金词染色（goldOf 单字数组）与字幕停留（assertHold ≥2.5s），有对应验证记录
- 台账记录本次修订（改了什么/影响哪些段/触发原因）

## eval 4 · 发布确认（hash 绑定）

**prompt**：（成片交付后）发布吧，标题用「用 AI 做视频：90 秒讲完锚定效应。」定时周五晚上 7 点。

**expected_output**：
- 出发布包（标题/简介/封面 cover.png+cover-4x3.png/定时时间），四要素序列化算 sha256 记入台账
- 用户确认绑定该 hash 后才进发布流程；确认前不进任何上传/草稿环节
- 若用户随后改标题：指出 hash 已变、重新确认后才更新
- 全程遵守发布红线：任何发布动作前有用户显式确认记录
